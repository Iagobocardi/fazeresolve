# Frontend Integration Guide: New Settings Page

This document provides instructions for integrating the new settings page (`public/configuracao.html`) with the backend API. The goal is to create a dynamic and responsive user experience by connecting the UI elements to the new backend endpoints.

## 1. Overview

The new settings page is designed to be populated by a single, unified API call on page load. Each user action (like saving a profile or changing a plan) then triggers a specific, dedicated API endpoint.

## 2. Initial Data Loading

On page load, make a single authenticated request to the following endpoint to fetch all the data needed to populate the entire settings page.

- **Endpoint:** `GET /api/configuracoes/all-data`
- **Method:** `GET`
- **Authentication:** Required.

## 3. Action Endpoints

The following endpoints should be called when the user performs a specific action.

### 3.1. Perfil Tab

- **Action:** Clicking "Salvar Alterações" for profile and address information.
- **Endpoint:** `PUT /api/configuracoes/perfil`
- **Request Body:**
  ```json
  {
      "nomeEmpresa": "Novo Nome da Empresa",
      "cnpjCpf": "11.111.111/0001-11",
      "telefone": "(11) 98888-7777",
      "endereco": {
          "cep": "11111-000",
          "logradouro": "Nova Rua",
          "numero": "123",
          "bairro": "Novo Bairro",
          "cidade": "Nova Cidade",
          "estado": "NS"
      }
  }
  ```

### 3.2. Plano e Assinatura Tab

- **Action:** Clicking "Upgrade" or "Downgrade" in the "Alterar Plano" modal.
- **Endpoint:** `POST /api/configuracoes/assinatura/alterar-plano`
- **Request Body:**
  ```json
  {
      "novoPlano": "Premium"
  }
  ```

- **Action:** Clicking "Sim, cancelar" in the "Cancelar Assinatura" modal.
- **Endpoint:** `POST /api/configuracoes/assinatura/cancelar`
- **Request Body:** (None)

- **Action:** Clicking "Salvar Alterações" in the "Atualizar método de pagamento" modal.
- **Endpoint:** `POST /api/configuracoes/assinatura/atualizar-pagamento`
- **Request Body:**
  ```json
  {
      "cardTokenId": "TOKEN_GERADO_PELO_FRONTEND"
  }
  ```
- **CRITICAL NOTE:** You **must** use the Mercado Pago frontend SDK (or a similar library) to securely tokenize the user's credit card information. **Never send raw card details to the backend.** Send only the `cardTokenId` generated by the SDK.

### 3.3. Recebimentos Tab

- **Action:** Clicking "Salvar Configurações" for payment reception settings.
- **Endpoint:** `PUT /api/configuracoes/recebimentos`
- **Request Body Example (Manual):**
  ```json
  {
      "metodo": "MANUAL",
      "chavePix": "nova-chave-pix@email.com"
  }
  ```
- **Request Body Example (Mercado Pago):**
  ```json
  {
      "metodo": "MERCADOPAGO"
  }
  ```

## 4. Integrações Tab

The buttons on this tab should use the existing endpoints, which remain unchanged.

- **Google Calendar:** `GET /api/configuracoes/google/connect` and `DELETE /api/configuracoes/google/disconnect`
- **WhatsApp:** The connection flow starts with `POST /api/configuracoes/whatsapp/iniciar-onboarding`.
- **Mercado Pago:** This is now linked to the "Recebimentos" tab. Selecting "Mercado Pago" as the payment method enables this integration.
- **Focus NFe:** This functionality is marked as "Em breve" and does not require an endpoint at this time.
